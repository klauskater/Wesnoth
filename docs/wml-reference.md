# WML порта: полный справочник

Этот документ описывает **реально поддерживаемый** WML в текущей версии порта.
Это самостоятельный компактный формат данных, похожий на WML Battle for
Wesnoth, но не совместимый с ним. Отличия собраны отдельно в
[wml-differences.md](wml-differences.md).

Источники истины для этого справочника:

- синтаксис — `src/wml.rs`;
- загрузка ресурсов — `src/game.rs`;
- игровое значение тегов — `scripts/rules/basic_combat.lua` и
  `scripts/rules/simple_ai.lua`;
- правила графики местности — `src/terrain_rules.rs`.

## 1. Модель языка

WML-файл содержит корневые теги. Тег имеет имя, уникальные атрибуты и дочерние
теги:

```wml
[unit_type]
    id=elvish_fighter
    name="Эльфийский воин"

    [attack]
        id=sword
        damage=6
        strikes=3
    [/attack]
[/unit_type]
```

Парсер не знает имён игровых тегов и атрибутов. Он только строит дерево.
`src/game.rs` загружает обязательные ресурсы и преобразует часть дерева в
универсальные значения. Остальные ограничения и игровую семантику применяют
Lua-правила.

Неизвестный тег или атрибут поэтому обычно не вызывает ошибку: он сохраняется
в дереве, но ничего не делает, пока его не прочитает загрузчик или Lua.

## 2. Синтаксис

### 2.1. Теги

Открывающий и закрывающий теги должны занимать отдельные строки:

```wml
[tag]
    key=value
    [child]
    [/child]
[/tag]
```

- Имена чувствительны к регистру.
- Вложенность произвольная.
- Закрывающий тег обязан совпадать с последним открытым.
- Несколько корневых тегов разрешены синтаксически.
- Пробелы до и после строки с тегом игнорируются.
- Атрибут вне тега является ошибкой.

### 2.2. Атрибуты

Атрибут записывается как `имя=значение`. Строка делится по первому знаку `=`:

```wml
id=first_battle
formula=a=b
```

Пробелы вокруг имени и значения удаляются. В одном теге имя атрибута может
встречаться только один раз. Повтор является ошибкой загрузки.

### 2.3. Значения

Поддерживаются три формы.

Обычная строка продолжается до конца строки:

```wml
id=player
recruit=elvish_archer,elvish_fighter
```

Парные внешние кавычки удаляются:

```wml
name="Первая битва"
```

Кавычки не имеют механизма экранирования. Внутренние кавычки просто остаются
частью результата, если вся строка начинается и заканчивается кавычкой.

Многострочное значение начинается только тогда, когда значение после `=`
равно `<<`. Завершающая строка после удаления пробелов должна быть равна `>>`:

```wml
data=<<
grassland,forest
hills,water
>>
```

Начальные и конечные пробельные символы всего блока удаляются. Переводы строк и
пробелы внутри блока сохраняются.

### 2.4. Комментарии

Пустые строки и строки, у которых первый непробельный символ — `#`,
игнорируются:

```wml
# комментарий на всю строку
id=map_1
```

Встроенных комментариев нет: `id=map_1 # text` задаёт буквальное значение
`map_1 # text`.

### 2.5. Типы после загрузки

Сам парсер хранит все атрибуты как строки. При передаче сценария, типа юнита и
их дочерних тегов в Lua каждое значение, которое целиком разбирается как
знаковое 64-битное целое, становится `integer`. Все остальные значения
остаются строками.

```wml
a=12       # integer 12
b="12"     # тоже integer 12
c=yes      # string "yes"
d=1.5      # string "1.5"
e=         # пустая string
```

Логического WML-типа нет. Lua-правила обычно сравнивают флаги с `"yes"`, а
созданные во время игры состояния могут быть настоящими Lua boolean.

Дочерние теги передаются в специальном поле `__children`:

```lua
node.__children.attack -- всегда список, даже для одного [attack]
```

Теги группируются по имени. Порядок одинаково названных тегов сохраняется;
общий порядок между тегами разных имён после преобразования в Lua не
сохраняется.

## 3. Загрузка файлов

Все пути в `[resources]` разрешаются относительно каталога `scripts/`.
Подстановки, glob-шаблоны и WML-включения отсутствуют.

Основные виды файлов:

| Каталог | Корневой тег | Назначение |
| --- | --- | --- |
| `scripts/scenarios/` | `[scenario]` | сценарий, стороны, объекты и условия |
| `scripts/maps/` | `[map]` | размеры и клетки карты |
| `scripts/map_objects/` | `[map_object]` | допустимые игровые типы местности |
| `scripts/units/` | `[trait]`, `[race]`, `[unit_type]` | traits, расы и шаблоны бойцов |
| `scripts/dialogs/` | `[dialog]` | реплики |
| `scripts/terrain/` | `[terrain_rule]` | отдельный диалект графики местности |

Сценарий, карта и каждый объект местности должны содержать ровно один корневой
тег ожидаемого имени. Ресурс юнитов может быть как одиночным `[unit_type]`, так
и каталогом из нескольких `[trait]`, `[race]` и `[unit_type]`; id уникальны в
пределах соответствующего вида. Для остальных загрузчиков посторонний корень
является ошибкой.

## 4. Сценарий

### 4.1. `[scenario]`

Обязательные атрибуты:

| Атрибут | Тип | Значение |
| --- | --- | --- |
| `id` | string | уникальный идентификатор сценария |
| `name` | string | отображаемое имя |
| `random_seed` | integer | seed детерминированного RNG |
| `on_start_dialog` | string | id начального диалога |

Обязателен один дочерний `[resources]`. Нужна хотя бы одна `[side]`, потому что
первая сторона становится активной.

Необязательные атрибуты:

| Атрибут | Тип / default | Значение |
| --- | --- | --- |
| `objective` | string | текст цели, если активная фаза не задаёт `label` |
| `next_scenario` | string | путь следующей главы после победы |
| `campaign_side` | string | сторона, чьи бойцы и золото переносятся |
| `carryover_percentage` | integer, `0` | процент переносимого золота |
| `recall_cost` | integer, `20` | цена возврата ветерана |
| `vision_radius` | integer, `2` | общий радиус обзора |
| `base_income` | integer, `0` | базовый доход стороны за ход |
| `village_income` | integer, `0` | доход с деревни |
| `village_support` | integer, `0` | содержание, покрываемое деревней |
| `village_heal` | integer, `0` | лечение в союзной деревне |
| `rest_heal` | integer, `2` | добавочное лечение за отдых |
| `max_healing` | integer, `8` | предел лечения за начало хода |
| `kill_experience` | integer, `8` | множитель XP за убийство |
| `combat_experience` | integer, `1` | множитель XP за бой без убийства |

Поддерживаемые дочерние теги: `[resources]`, `[side]`, `[unit]`, `[village]`,
`[objective]`, `[phase]`, `[choice]`, `[turn_event]`, `[location_event]`,
`[attack_event]`, `[achievement]`.

### 4.2. `[resources]`

Все пять атрибутов обязательны:

| Атрибут | Формат |
| --- | --- |
| `map` | один путь к WML-карте |
| `map_objects` | CSV путей к определениям местности |
| `unit_types` | CSV путей к типам юнитов |
| `dialogs` | один путь к файлу с диалогами |
| `rules` | упорядоченный CSV путей к Lua-файлам |

Пустые элементы CSV игнорируются. Lua-файлы соединяются переводом строки и
исполняются как один chunk; последний файл должен вернуть таблицу публичных
функций правил.

### 4.3. `[side]`

| Атрибут | Тип / значения | Значение |
| --- | --- | --- |
| `id` | string, обязателен | идентификатор стороны |
| `controller` | `human` или `ai` | тип управления |
| `team_name` | string | одинаковое непустое имя делает стороны союзниками |
| `defeat_condition` | `no_units_left` / `no_leader_left` / `never` | условие поражения; default `no_units_left` |
| `gold` | integer, `0` | начальное золото |
| `recruit` | CSV id типов | общий список найма |
| `base_income` | integer | переопределение значения сценария |
| `village_income` | integer | переопределение дохода с деревни |
| `village_gold` | integer | синоним `village_income` только для стороны |
| `village_support` | integer | переопределение поддержки |
| `fog` | `yes` | включить текущий туман войны |
| `shroud` | `yes` | включить постоянную неисследованную область |
| `vision_radius` | integer | переопределить радиус обзора |

Параметры AI: `aggression` (default 1), `caution` (1), `grouping` (4),
`leader_caution` (2), `patience` (3), `objective_weight` (14),
`attack_threshold` (-20) и `passive_leader=yes`. Это числовые веса utility-AI,
а не гарантии конкретного поведения.

Дочерний `[recruit_hex]` встречается в данных, но текущая версия правил его не
читает. Доступные клетки найма вычисляются по связной области `castle`,
примыкающей к `keep` с лидером.

### 4.4. `[unit]`

Экземпляр накладывается поверх `[unit_type]`.

| Атрибут | Тип | Значение |
| --- | --- | --- |
| `id` | string, обязателен | уникальный id объекта |
| `type` | string, обязателен | существующий `[unit_type].id` |
| `side` | string | сторона |
| `x`, `y` | integer | начальная 1-based позиция |
| `name` | string | имя экземпляра |
| `initial_hitpoints` | integer | начальные HP вместо максимума |
| `experience` | integer, `0` | начальный XP |
| `max_hitpoints`, `max_moves`, `alignment` | как у типа | локальное переопределение |
| `is_leader`, `canrecruit` | `yes` | юнит может нанимать и считается лидером |
| `extra_recruit` | CSV id типов | дополнительный личный список найма |
| `upkeep` | integer / `free` / `loyal` | содержание |
| `reserve_group` | string | не ставить на карту до появления группы |
| `event_group` | string | группа, удаляемая правильным выбором |
| `hidden` | `yes` | скрывать от врагов до соседнего обнаружения |
| `poisoned`, `slowed`, `petrified`, `unhealable`, `stunned` | `yes` | начальные состояния |

`hitpoints`, `movement_points`, `attacks_left`, `position`, `resting` и
аналогичные поля — производное состояние Lua. Их не следует задавать в новом
WML, кроме состояния, восстановленного самой игрой.

Если у `[unit]` появляются собственные дочерние теги, его `__children` целиком
заменяет `__children` типа, а не сливается с ним.

### 4.5. `[village]`

`x` и `y` обязательны и должны указывать клетку, которую движок классифицирует
как `village`. Необязательный `side` задаёт первого владельца.

## 5. Завершение, фазы и события

### 5.1. `[objective]`

Общие атрибуты: обязательный `result` (`victory` или `defeat`), необязательный
`dialog`; `side`, `unit`, `turn` и дочерние теги зависят от условия `when`.

| `when` | Дополнительные данные | Когда срабатывает |
| --- | --- | --- |
| `side_defeated` | `side` | выполнен `defeat_condition` стороны |
| `enemies_defeated` | `side` | побеждены все не союзные указанной стороне |
| `locations_controlled` | `side`, один или больше `[location]` | все клетки контролируются союзниками |
| `unit_defeated` | `unit` | погиб указанный юнит |
| `turn_limit` | `turn` | текущий ход стал больше лимита |

`[location]` содержит integer `x`, `y`. Обычную клетку контролирует стоящий на
ней союзный юнит, деревню — её союзный владелец.

Если при выполнении цели известен убийца, `killer_variable=name` записывает его
id в `campaign:name`. Каждый дочерний `[campaign_variable]` с `name` и `value`
записывает `value` в `campaign:name`. Значение уже прошло обычное преобразование
строка/integer.

Цели проверяются по порядку; срабатывает первая совпавшая.

### 5.2. `[phase]`

Первая фаза в документе активируется при инициализации.

| Атрибут | Значение |
| --- | --- |
| `id` | обязательный id |
| `label` | текст текущей цели для UI |
| `when=unit_reaches` | `unit` достигает `x`,`y`; `side` может ограничить сторону |
| `when=unit_defeated` | погибает `unit` |
| `when=turn_reached` | юнит `unit` (если указан) удерживает `x`,`y` в течение `turns` ходов |
| `next` | следующая фаза |
| `spawn_group` | вывести резерв с таким `reserve_group` |
| `dialog` | диалог при входе в фазу |
| `choice` | запросить сценарный выбор при достижении клетки |
| `advance_when_side_defeated` | перейти к `next`, когда сторона побеждена |
| `result` | закончить сценарий вместо перехода |
| `finish_dialog` | диалог завершения; fallback — `dialog` |

### 5.3. `[choice]` и `[option]`

`[choice]` имеет обязательный `id` и дочерние `[option]` с обязательным `id`.
`dialog` показывается при запросе выбора.

Правильный ответ сравнивается сначала со значением состояния из
`expected_variable`, иначе с буквальным `expected`, иначе с `fallback`.
`correct_dialog` и `wrong_dialog` задают результат. При правильном ответе
`remove_group` удаляет объекты с совпадающим `event_group`. `next` переводит в
следующую фазу независимо от правильности ответа.

Пока выбор ожидается, остальные игровые команды заблокированы.

### 5.4. `[turn_event]`

Одноразовое событие на ходу `turn`. Необязательны `id`, `dialog`,
`spawn_group`, `choice`. Если `id` отсутствует, ключом одноразовости служит
номер хода. На одном ходу обрабатывается первое подходящее событие.

### 5.5. `[location_event]`

Одноразовое событие при входе объекта на `x`,`y`. `id`, `x`, `y` обязательны;
`side` ограничивает сторону. Эффекты можно сочетать:

- `dialog` — запрос диалога;
- `gold` — изменение золота стороны вошедшего объекта;
- `damage` — урон, который не может опустить HP ниже 1;
- `status` — установить одноимённое boolean-поле объекта;
- `achievement` — записать `campaign:achievement:<id>`.

### 5.6. `[attack_event]`

Одноразовое событие с обязательным `id`. `attacker` и `defender` необязательно
ограничивают id участников. `dialog` используется после боя без убийства,
`kill_dialog` — когда в бою погиб любой участник. `achievement` открывается
только при гибели защищающегося.

### 5.7. `[achievement]`

| `when` | Поля | Значение |
| --- | --- | --- |
| `victory` | `id`, optional `unless_state` | открыть при победе, если указанное состояние ложно |
| `unit_defeated` | `id`, `unit`, optional `killer` | открыть за нужное убийство |

Результат хранится как `campaign:achievement:<id>` и переносится между главами.

## 6. Типы юнитов

### 6.1. `[unit_type]`

| Атрибут | Требование / значение |
| --- | --- |
| `id` | обязателен и уникален среди загруженных типов |
| `name` | отображаемое имя; fallback в UI — id |
| `max_hitpoints` | обязательное integer для игрового типа; на практике должно быть положительным |
| `max_moves` | обязательное integer |
| `level` | обязательное integer, `0` не создаёт зону контроля |
| `max_experience` | обязательное integer |
| `advances_to` | CSV id следующих типов; пусто означает отсутствие повышения |
| `alignment` | обязательное значение; `lawful` и `chaotic` имеют бонусы, остальные ведут себя как neutral |
| `cost` | integer, обязателен для найма |
| `race` | id загруженной `[race]`; используется для выбора traits |
| `image` | путь базового спрайта в оригинальном дереве ресурсов |
| `movement_type` | исходный id movetype; таблицы движения уже развёрнуты импортёром |
| `num_traits` | локальное переопределение числа случайных traits |

Игровому типу также нужны `[movement_costs]`, `[defense]`, `[resistance]` и хотя
бы один `[attack]` для полноценного участия в игре.

### 6.2. `[movement_costs]`, `[defense]`, `[resistance]`

Это карты `имя -> integer` с произвольными ключами.

- `[movement_costs]`: стоимость входа для каждого результата
  `gameplay_type`; отсутствующий ключ делает местность непроходимой.
- `[defense]`: процент уклонения цели; шанс попадания равен `100 - defense`.
- `[resistance]`: процент сопротивления по `damage_type`; отрицательное число
  увеличивает урон.

Текущие игровые типы местности: `grassland`, `forest`, `hills`, `water`,
`castle`, `keep`, `village`. Основные типы урона: `blade`, `pierce`, `impact`,
`fire`, `cold`, `arcane`.

### 6.3. `[attack]` и `[special]`

`[attack]`:

| Атрибут | Значение |
| --- | --- |
| `id` | обязательный id; при повторах поиск выберет первую атаку |
| `name` | отображаемое имя; fallback — id |
| `range` | обычно `melee` или `ranged`; ответ выбирается по точному совпадению строки |
| `damage_type` | ключ в `[resistance]` цели |
| `damage` | базовый урон одного удара |
| `strikes` | число ударов |
| `defense_weight` | `0` запрещает выбирать атаку для ответа; иначе вес выбора |

Каждый дочерний `[special]` содержит `id`. Реализованы:

| id | Эффект |
| --- | --- |
| `magical` | шанс попадания ровно 70% |
| `marksman` | при атаке шанс не ниже 60% |
| `poison` | накладывает яд |
| `slow` | замедляет и вдвое уменьшает урон/MP |
| `petrify` | останавливает бой и блокирует юнита без срока |
| `stun` | блокирует до конца хода стороны |
| `drain` | лечит атакующего на половину фактического урона |
| `berserk` | до 30 раундов или до гибели/окаменения |
| `first_strike` | защитник наносит первый удар, если у атакующего нет того же special |
| `backstab` | удваивает урон при союзнике на противоположной стороне цели |
| `charge` | удваивает урон атакующего и ответный урон |
| `swarm` | уменьшает число ударов пропорционально текущим HP |
| `plague` | после убийства создаёт указанный тип на клетке жертвы |
| `absorb` | уменьшает урон противника множителем special |
| `deflect` | уменьшает шанс попадания противника |

Неизвестный `special.id` сохраняется, показывается клиенту, но правил не меняет.

### 6.4. `[ability]`

`id` обязателен; `value` нужен числовым способностям, `terrain` — засаде.

| id | Эффект |
| --- | --- |
| `leadership` | +25% урона за каждый уровень превосходства соседнего лидера |
| `heals` | лечит соседнего союзника на `value`, защищает от урона ядом |
| `cures` | лечит на `value` и снимает яд |
| `regenerates` | лечит себя на `value` и снимает яд |
| `steadfast` | в защите удваивает положительное сопротивление, максимум до 50% |
| `teleport` | перемещение за 1 MP между свободными союзными деревнями |
| `skirmisher` | игнорирует остановку в зоне контроля |
| `ambush` | скрывает на `terrain`; без `terrain` — на любой местности |
| `concealment` | скрывает в деревне |
| `submerge`, `swamp_lurk` | скрывают в воде текущей укрупнённой модели местности |
| `burrow` | скрывает отдыхающего в лесу/на суше |
| `nightstalk` | скрывает ночью |
| `illuminates` | повышает локальный lawful bonus до дневного предела |
| `feeding` | после убийства живой цели добавляет 1 к максимальным HP |

Для одинаковых источников лечения применяется максимальное значение, а не
сумма. Неизвестная способность сохраняется, но не действует.

### 6.5. `[trait]` и `[race]`

Каталог может объявить глобальные `[trait]` и расовые traits внутри `[race]`.
При создании юнита детерминированный RNG выбирает `num_traits` без повторов;
traits с `availability=musthave` добавляются всегда. Реализованы оригинальные
`[effect]` для HP, движения, порога опыта, атак и статусов
`healthy`/`fearless`/`loyal`. Выбранные id и изменённые характеристики входят
в сохранение и snapshot, а при повышении traits повторно накладываются на новый
тип.

## 7. Карты и местность

### 7.1. `[map]`

Обязательны `width`, `height` и `data`; `id` используется как метаданные.
`data` состоит из строк сверху вниз и CSV-клеток слева направо. Число строк и
клеток обязано точно совпадать с размерами.

```wml
[map]
    id=example
    width=2
    height=2
    data=<<
Gg,Gg^Fms
Kh,Ch
    >>
[/map]
```

Поддерживаются как простые имена порта, так и исходные коды Wesnoth. Для
игровых правил код классифицируется так:

1. overlay `B*` → `grassland`, `V*` → `village`, `F*` → `forest`;
2. base `K*` → `keep`, `C*` → `castle`, `W*` или `Ss` → `water`, `H*`/`M*`
   → `hills`;
3. буквальные `forest`, `hills`, `water`, `castle`, `keep`, `village`
   сохраняют тип;
4. всё остальное становится `grassland`.

Графический клиент продолжает видеть исходный код клетки. Поэтому неизвестный
код может быть игровым `grassland`, но не иметь подходящей графики.

### 7.2. `[map_object]`

В текущей версии используется только обязательный `id`. Он объявляет игровой
тип местности допустимым для сценария. Остальные атрибуты и дочерние теги
синтаксически сохраняются, но загрузчиком не читаются.

Сценарий обязан загрузить определения для всех результатов классификации клеток
карты. Повторный `id` — ошибка.

## 8. Диалоги

Файл может содержать несколько корневых `[dialog]`:

```wml
[dialog]
    id=intro
    [line]
        speaker=narrator
        text="Текст реплики"
    [/line]
[/dialog]
```

`dialog.id`, а также `line.speaker` и `line.text` обязательны. В диалоге должна
быть хотя бы одна строка. Порядок `[line]` сохраняется. Повторный id диалога —
ошибка. Существование id, указанного событием, проверяется только когда диалог
запрашивается.

## 9. WML графики местности

`scripts/terrain/graphics.wml` использует тот же синтаксический парсер, но
отдельную схему. Допустимы только корневые `[terrain_rule]`.

### 9.1. `[terrain_rule]`

| Атрибут | Тип / default | Значение |
| --- | --- | --- |
| `id` | string, обязателен | id; развёрнутый вариант получает суффикс `:<turn>` |
| `probability` | integer 0..100, `100` | детерминированная вероятность применения |
| `rotations` | integer 1..6, `1` | создать повороты `0..rotations-1` |
| `rotation_turns` | CSV integer 0..5 | явно выбрать повороты; имеет приоритет |
| `rotation_names` | CSV ровно из 6 строк | имена направлений; default `n,ne,se,s,sw,nw` |

Нужны хотя бы один `[constraint]` и один `[image]`. Правила применяются в
порядке файла ко всем клеткам карты. Вероятность стабильна для сочетания seed,
индекса правила и координаты.

### 9.2. `[constraint]`

| Атрибут | Тип / default | Значение |
| --- | --- | --- |
| `terrain` | CSV, обязателен | разрешённые шаблоны исходного кода клетки |
| `exclude` | CSV | запрещённые шаблоны |
| `q`, `r` | integer, `0` | аксиальное смещение от якоря до поворота |
| `forbid_flags` | CSV | требовать отсутствия флагов в проверяемой клетке |
| `set_flags` | CSV | установить флаги после совпадения всего правила |

В шаблонах `terrain` и `exclude` символ `*` совпадает с любой
последовательностью. Клетка за картой имеет служебный код `_offmap`.

Поворот заменяет `@R0`…`@R5` в именах флагов согласно `rotation_names` и
поворачивает `(q,r)` на соответствующее число граней.

### 9.3. `[image]`

| Атрибут | Тип / default | Значение |
| --- | --- | --- |
| `name` | string, обязателен | логический ключ изображения; поддерживает `@R0`…`@R5` |
| `layer` | integer, `0` | меньший слой рисуется раньше |
| `base` | пара `x,y`, `0,0` | вторичный ключ сортировки |
| `center` | пара `x,y` | сохранённая точка привязки |

`name` не является путём к произвольному PNG: клиент должен знать этот
логический ключ. `center` сейчас загружается, но клиент использует собственные
точки привязки.

## 10. Ошибки и валидация

Парсер сообщает номер строки для пустого или некорректного имени тега/атрибута,
неожиданного/неверного закрывающего тега, атрибута вне тега, строки без `=`,
незавершённого `<<` и повторного атрибута.
Незакрытый тег сообщается после конца файла.

Rust-загрузчик дополнительно проверяет:

- наличие обязательных корней, атрибутов и ресурсов;
- уникальность id типов юнитов, объектов, диалогов и map objects;
- существование типа каждого `[unit]`;
- прямоугольность карты;
- наличие объявленного игрового типа для каждой клетки.

Lua `initialize` затем проверяет позиции, их уникальность, наличие основных
полей типов и корректность настроенных деревень. Многие ссылки проверяются
лениво только при использовании. Полной схемной валидации неизвестных полей
нет, поэтому опечатка может остаться незамеченной.

## 11. Минимальный сценарий

```wml
[scenario]
    id=example
    name="Пример"
    random_seed=1
    on_start_dialog=intro

    [resources]
        map=maps/example.wml
        map_objects=map_objects/grassland.wml
        unit_types=units/fighter.wml
        dialogs=dialogs/example.wml
        rules=rules/simple_ai.lua,rules/basic_combat.lua
    [/resources]

    [side]
        id=player
        controller=human
    [/side]

    [side]
        id=enemy
        controller=ai
    [/side]

    [unit]
        id=hero
        type=fighter
        side=player
        x=1
        y=1
    [/unit]

    [objective]
        result=victory
        when=enemies_defeated
        side=player
        dialog=victory
    [/objective]
[/scenario]
```

Полные рабочие примеры находятся в `scripts/scenarios/`, `scripts/units/`,
`scripts/maps/` и `scripts/dialogs/`.
