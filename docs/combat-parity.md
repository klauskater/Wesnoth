# Сравнение боевых правил с Wesnoth 1.19.27+dev

Эталон выбран пользователем: локальные исходники `Wesnoth-upstream`, не 1.18.8.
SHA-256 исходников и схем зафиксированы в `combat-upstream-reference.json`.
Импортированный каталог юнитов пока остаётся 1.18.8. Смена эталона правил не означает,
что каталог автоматически обновлён.

**Полное соответствие не достигнуто.** Этот документ отделяет проверенные исправления
от оставшихся расхождений. «Проверено» означает конкретные регрессионные примеры,
а не доказательство поддержки любых WML/WFL или всех комбинаций атрибутов.

## Граница реализации

- Lua определяет параметры оружия, активность эффектов, порядок ударов, статусы,
  стоимость действия, опыт, превращения и события сценария. Юниты — данные скриптов.
- Rust предоставляет транзакции и общие операции над игровым состоянием. Численный
  прогноз получает готовые параметры и последовательность от Lua; имена способностей,
  условия WML, правила округления модификаторов и число раундов берсерка туда не переносятся.
- Применение результата и показ используют один журнал ударов; клиент не вычисляет
  шанс попадания или урон. Прогноз и исполнение используют одну подготовку боя.
- Численное ядро пока специализировано на двух участниках и фиксированных параметрах
  обмена с альтернативным уроном при замедлении. Произвольные события между ударами
  в нём не моделируются. Это ограничение необходимо устранить/явно учитывать до заявления
  о полном соответствии прогнозов оригиналу.

## Обнаруженные и исправленные расхождения

| Механизм | Было | Сейчас и проверка |
|---|---|---|
| Округление | `floor(x+0.5)`, могло дать 0 при положительной атаке | `round_damage`: половины в сторону базового урона, минимум 1 для ненулевой базы; нулевая база остаётся 0 |
| Умножение урона | Charge/backstab после округления | Изменяется базовый урон до времени суток/сопротивления/округления |
| Попадание | Magical/marksman до accuracy/parry | Сначала ограничение base+accuracy−parry, потом `chance_to_hit`, затем итоговый диапазон 0–100 |
| Числовые specials | Несколько известных ID | Обработка по `kind`, произвольные ID, value/add/sub/multiply/divide, приоритеты, дедупликация по ID, min/max и filter_base_value |
| Контекст specials | Обычно проверка наличия ID | `active_on=both/offense/defense`, `apply_to=self/opponent/both/attacker/defender`; базовые фильтры участников/оружия |
| Berserk | По 30 ударов каждой стороне | Полные раунды с исходным числом ударов каждого оружия и первым ударом в каждом раунде; `value` задаёт раунды |
| Swarm | Не меньше одного удара | Допускает 0, учитывает swarm_attacks_min/max; перед swarm применяется `attacks` |
| Firststrike | Известный ID | В том числе исходный kind и контекст; два firststrike возвращают приоритет атакующему |
| Drain | Всегда 50%, иммунитет не учитывался | Числовые атрибуты drains, undrainable, фактически нанесённый урон |
| Heal-on-hit | Не было | Постоянная прибавка/убыль на попадании, ограничение максимальным HP и минимумом 1 у источника |
| Иммунитеты | Частично терялись/игнорировались | unpoisonable, undrainable, unslowable, unpetrifiable, invulnerable; сохранение расовых статусов стартовых юнитов |
| Статусы при смерти | Могли накладываться на уже погибшего | Poison/slow/petrify только на пережившую удар цель |
| Расход действия | Всегда все ходы и одна атака | movement_used и attacks_used оружия |
| Alignment | Только свойство юнита | Переопределение оружием; добавлен liminal без утверждения полной поддержки расписаний |
| Тип урона | Только type оружия | replacement_type и alternative_type по базовым сопротивлениям; полный контекст resistance-способностей ещё нужен |
| Disable | Не учитывался | Контекстный запрет оружия в исполнении, прогнозе и выборе ответного оружия |
| Дистанция | Только соседние гексы | min_range/max_range в правилах доступности, ответной атаке и ИИ; клиент скрывает недоступные варианты |
| Plague | Не было unplagueable, тип по умолчанию фиксирован | Проверка unplagueable; по умолчанию тип убийцы; остальные ограничения ниже |

Исполняемые примеры: `tests/combat_parity.rs`, `tests/fixtures/combat_parity.lua`.
Это тесты по прочитанной реализации upstream. Сам upstream-бинарник в качестве
дифференциального оракула пока не запускался.

## Все поля attack из текущей схемы

Источник: `data/schema/units/types.cfg`, `src/units/attack_type.cpp`.

| Поле upstream | Состояние |
|---|---|
| name | Импортируется как id; выбор оружия по id |
| description | Импортируется как name; отображение |
| icon | Сохраняется импортёром; отдельная проверка отображения нужна |
| type | Импортируется как damage_type; замена/альтернатива поддержана с ограничениями выше |
| range | Совпадение категории для ответа (melee/ranged); это не дистанция в гексах |
| alignment | Сохраняется импортёром, переопределяет alignment юнита |
| damage, number | damage/strikes, модификаторы до расчёта обмена |
| defense_weight | Выбор ответа по ожидаемому прямому урону; сложные критерии upstream ещё не воспроизведены |
| attack_weight | ИИ исключает неположительные веса; точная сравнительная оценка весов ещё не перенесена |
| movement_used, attacks_used | Импорт и исполнение |
| accuracy, parry | Исправлен порядок относительно chance_to_hit |
| min_range, max_range | Импорт, исполнение, выбор целей/ответа |
| specials_list | Реестр specials upstream пока не разрешается |
| __remove | Семантика удаления при слиянии WML пока не реализована |
| specials (дочерний узел) | Преобразуется в список special с сохранением kind; полнота условий ниже |

## Все семейства specials и их атрибуты

Источник: `data/schema/units/specials.cfg`.

Общие поля каждого special:
`name`, `name_inactive`, `description`, `description_inactive`, `special_note`,
`id`, `unique_id`, `active_on`, `apply_to`.
Тексты и идентификаторы сохраняются; произвольные unique_id/реестры и выбор активной
подписи в интерфейсе не закончены. `active_on`/`apply_to` реализованы.

Общие дочерние конструкции:
`filter_self`, `filter_opponent`, `filter_attacker`, `filter_defender`, вложенный
`filter_weapon`, `filter_adjacent`, `filter_adjacent_location`, `event`, WML merge keys.
Фильтры простых полей участников и оружия реализованы частично. Формулы, соседние
фильтры, события и слияние не соответствуют оригиналу. Стандартная формула backstab
обрабатывается отдельной геометрической проверкой; это не интерпретатор WFL.

| Семейство | Дополнительные атрибуты | Оставшееся |
|---|---|---|
| attacks | Все числовые атрибуты | WFL/полные фильтры/подавление |
| chance_to_hit | Все числовые атрибуты | То же |
| damage | Все числовые атрибуты, deprecated backstab | То же; старые WML-формы проверить отдельно |
| drains | Все числовые атрибуты | То же |
| heal_on_hit | Все числовые атрибуты | То же |
| damage_type | replacement_type, alternative_type | Сопротивления с активными способностями; suppression |
| berserk | value, cumulative | WFL, suppression и крайние значения |
| plague | type | Вариации создаваемого юнита, события смерти/замены, suppression |
| swarm | swarm_attacks_min, swarm_attacks_max, cumulative | WFL и suppression |
| firststrike | Только общие | Общие неподдержанные фильтры и weapon-like abilities |
| poison | Только общие | Те же ограничения; прогноз состояния poison отсутствует |
| slow | Только общие | Те же ограничения; стоимость движения замедленного требует отдельного исправления |
| petrifies | Только общие | Те же ограничения |
| disable | Только общие | Те же ограничения |
| произвольный тег * | Произвольные атрибуты | Нельзя считать поддержанным без обработчика событий/правил |

«Все числовые атрибуты» в схеме:
`value`, `add`, `sub`, `multiply`, `divide`, `max_value`, `min_value`, `priority`,
`cumulative`, deprecated `backstab`, дочерний `filter_base_value`.
Числовые константы работают. Варианты значений WFL (`s_f_int`, `f_int`, `f_real`)
**не реализованы**: арифметические поля с формулой отклоняются, а не подменяются нулём.

`filter_base_value` содержит все шесть сравнений:
`equals`, `not_equals`, `less_than`, `greater_than`, `less_than_equal_to`,
`greater_than_equal_to` — проверяются для текущей базовой величины группы приоритета.

Подавление пока **не реализовано**:
старый атрибут `overwrite_specials`, узел `overwrite` с `filter_specials`/
`experimental_filter_specials` и `priority`; новый `overwrite_specials` с `affect`,
`filter_special`, `priority`. Приоритет вычисления числового эффекта не равен
приоритету подавления другого эффекта.

## Все семейства abilities

Источник: `data/schema/units/abilities.cfg`.

Общие поля: `name`, `female_name`, `name_inactive`, `female_name_inactive`,
`description`, `description_inactive`, `special_note`, `affect_self`, `affect_allies`,
`affect_enemies`, `id`, `unique_id`, `halo_image`, `halo_image_self`, `overlay_image`,
`overlay_image_self`.

Общие конструкции: `filter`, `filter_self`, `filter_adjacent`,
`filter_adjacent_location`, `filter_base_value`, `affect_adjacent` с `adjacent`,
`radius`, вложенным `filter`; `event`; WML merge keys.
**Общего полностью совместимого вычислителя abilities пока нет.** Ниже — существующие
частные обработчики, которые нельзя выдавать за полную реализацию этих атрибутов.

| Семейство | Атрибуты сверх общих | Состояние |
|---|---|---|
| heals, regenerate | value, poison и все числовые атрибуты | Есть отдельные heals/cures/regenerates; порядок лечения, подавление, poison=cured/slowed и фильтры не полностью совпадают |
| defense | Числовые атрибуты | Общая способность изменения защиты не реализована |
| resistance | Числовые, apply_to, active_on, filter_weapon, filter_second_weapon | Есть частный steadfast; общий вычислитель отсутствует |
| leadership | Числовые, filter_weapon, filter_second_weapon, filter_opponent, filter_student | Пока формула по разнице уровней; значение/формулы/фильтры исходного WML не воспроизведены |
| illuminates | Числовые, radius | Частный illuminates; отрицательные значения, радиус, min/max, совмещение и расписания требуют переноса |
| hides | alert | Частные ambush/nightstalk/submerge и др.; произвольные условия отсутствуют |
| teleport | tunnel | Частный переход между деревнями; произвольные source/target/filter и параметры tunnel отсутствуют |
| weapon-like abilities | attacks, swarm, chance_to_hit, damage, damage_type, drains, heal_on_hit, berserk, plague, firststrike, poison, slow, petrifies, disable; name_affected, description_affected, filter_student | Пока не собираются вместе с specials оружия по полным правилам upstream |
| * | Произвольные атрибуты | Требует событий/пользовательских обработчиков |

Числовые abilities также имеют `overwrite_abilities/filter_ability/priority`.
Это отдельный незавершённый механизм. В `tunnel` схема перечисляет `id`, `filter`,
`source`, `target`, `bidirectional`, `always_visible`, `allow_vision`,
`pass_allied_units`, `delayed_variable_substitution`; они не покрыты частным teleport.

## Данные юнита, местность и результат

- Defense caps: importer превращает -70 в 170. Нужны раздельные значения защиты и
  ограничений, а также upstream-правила aliasof/def_alias для составной местности.
  Простое ограничение отображаемого процента диапазоном 0–100 скроет ошибку.
- Результаты модификаций юнита: поддержаны только некоторые apply_to. Полный EffectWML,
  наследование, вариации, порядок object/trait/advancement и временные эффекты — открыто.
- max_attacks: восстановление атак всё ещё обычно до 1; нужно привязать к данным юнита.
- Статусы: базовые иммунитеты добавлены; весь открытый словарь status и сценарные
  обработчики не проверены. Stun из макроса upstream — событие, наш отдельный stunned
  нельзя без проверки считать точным эквивалентом.
- Slow: урон проверен; расход движения/момент изменения движения — отдельное расхождение.
- Fearless/healthy, poisoned/resting, временные эффекты, лечение/регенерация/деревни:
  необходима сверка порядка событий начала и конца стороны.
- XP, AMLA, продвижение и несколько продвижений, убийство обоих участников,
  plague/feeding, события attack/attack_end/hits/misses/die/last_breath:
  частные реализации существуют, полного порядка событий upstream нет.
- Правильный выбор ответного оружия в сложных случаях должен учитывать способности
  и вероятность результата так же, как upstream; линейного damage×strikes×chance недостаточно.
- Прогноз не отслеживает распределения poison, XP/продвижения или сценарных событий.
  Совпадение средних HP ещё не доказывает совпадение полного результата боя.
- UI: журнал ударов остаётся источником результата; способности/описания и все условия
  их активности пока не отображаются полностью. Спрайт поздно нанятого гуля — отдельная
  проблема загрузки изображений, не отсутствующая механика боя.
- AI: общий прогноз и доступность оружия используются; тактическая оценка эффектов,
  геометрическая эвристика расстояния и сравнение вариантов не являются портом AI upstream.

## Критерий завершения

1. Сохранить порядок WML-узлов и реализовать полные фильтры/WFL, merge и registry.
2. Собрать единый контекст эффектов: оружие обеих сторон, способности обоих юнитов
   и соседей, фильтры, overwrite, priority и вычисление формул.
3. Исправить terrain aliases/defense caps и импорт атрибутов/вариаций/статусов.
4. Воспроизвести жизненный цикл боя и все события/эффекты результата.
5. Запустить дифференциальные сценарии на закреплённом upstream и порте: одинаковые
   входные данные и заданная последовательность попаданий, сравнение каждого события,
   HP/статусов/XP/остатков действий и распределений прогноза.
6. Проверить все поля указанных схем, их отрицательные/нулевые/граничные значения,
   сочетания и динамические изменения. Только после этого отмечать полное соответствие.
