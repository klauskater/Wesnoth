# Движение: граница Rust / Lua

Lua определяет правила: право на ход, бюджет, цены террейна, враждебность,
блокирующих юнитов, источники зон контроля и телепортацию. Rust ищет путь
по карте, которую держит у себя. Поиск не вызывает Lua и не выгружает карту.
Захват деревень, события и применение команды `move` остаются в правилах Lua.

## Контракт поиска

`context.map:search { start, budget, max_step, costs, occupied, blocked,
stop_near, destination, paths }`

- `costs`: тип террейна → положительная стоимость; отсутствие типа запрещает проход.
- `occupied`: нельзя закончить движение; проход разрешён, если клетки нет в `blocked`.
- `blocked`: проход запрещён.
- `stop_near`: позиции, соседние клетки которых останавливают поиск.
  Стартовая клетка сама по себе не останавливает выход.
- `max_step`: максимальная проходимая стоимость. Если шаг допустим, но превышает
  остаток бюджета, он расходует остаток — сохранённое правило существующего движения.
- `destination`: необязательно; возвращается только маршрут до одной цели.
- `paths=false`: не строить и не возвращать маршруты. Используется подсветкой и ИИ.
  По умолчанию маршруты возвращаются для совместимости.

Ответ: список `{ position, cost, zoc, path? }`. Поиск использует очередь с
приоритетом и таблицу предшественников. Порядок соседей и FIFO для одинаковой
стоимости сохраняют выбор маршрута прежнего Lua-алгоритма.

`combat.reachable` готовит ограничения одним пакетом. Специальное прямое
перемещение между деревнями остаётся в Lua и сохраняет прежнюю семантику.
`combat.move` заново проверяет текущие условия, запрашивая только целевой маршрут.

## Что пересекает границу языков

`objects:get(id, fields?, child_names?)`, `objects:all(fields?)` и
`state:get(key, fields?, child_names?)` позволяют выбирать нужные поля.
Без списков полей старые вызовы сохраняют прежний результат.
Списки `child_names` выбирают только указанные узлы внутри `__children`.

Для движения читаются одна сокращённая запись выбранного юнита, сокращённые
записи остальных юнитов и настройки сторон. Оружие, сопротивления, каталог
типов юнитов и остальные данные сценария в поиск не передаются.
Сериализация идёт прямо из заимствованного Rust-состояния, без промежуточного
клонирования дерева `Value`.

Мир хранится как `Rc<World>`. Читающий запрос разделяет снимок состояния;
первая запись транзакции вызывает `Rc::make_mut`, создавая независимую копию.
Успешная команда публикует её, ошибка или запрос `query` отбрасывают изменения.
Генератор случайных чисел также остаётся транзакционным. Это пока копирование
всего мира при первой записи, не журнал отдельных изменений.

Подсветка кэшируется по фокусу и ревизии игры: перерисовка, панорамирование
и масштабирование сами по себе не запускают поиск.

## Проверки и воспроизводимый замер

`cargo test --test pathfinding_bridge -- --nocapture`

Проверяет совпадение со старым алгоритмом на десяти сценариях и считает
вызовы/элементы данных на границе языков. Старый поиск хранится только в
`tests/fixtures/legacy_reachable.lua`; в клиент не попадает.

`cargo test --test pathfinding_bridge movement_benchmark -- --ignored --nocapture`

500 запросов для Арвита в первом сценарии. Замер сравнивает прежний Lua-поиск
с маршрутами и новый поиск для подсветки без маршрутов, оба на текущем движке.
Время зависит от компьютера; автоматические проверки фиксируют поведение и
структуру обмена, а не нестабильный порог миллисекунд.

Оптимизация не распространяется автоматически на остальные расчёты ИИ и боя:
их старые обращения к полным объектам нужно оценивать отдельно.
