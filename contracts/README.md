# Контракты системы

Контракт — договорённость между поставщиком модуля и его потребителями:
операции, входы/выходы, гарантии, ошибки, владение данными и побочные эффекты.
Интерфейс функций и типов — часть контракта. Отдельный trait или сервис ради
контракта не требуется.

Это целевые обязательства, пока не реализованные. Каждый модуль архитектуры
ссылается на контракт; каждый контракт перечисляет потребителей и зависимости.
API описывается в contracts, ответственность и размещение — в design.
При создании модуля ссылка на контракт включается в его верхний комментарий.

## Правило изменения

Целевой контракт сначала конкретизируется для используемых операций, затем
реализуется с проверкой его гарантий. Статус «реализован» ставится вместе с
переводом потребителей и фактическими результатами проверки.
Изменение существующего поведения требует согласованного изменения контракта,
кода и затронутых проверок. Если действующий код расходится с целевым контрактом,
это задача миграции; если со своим реализованным контрактом — дефект.
