# Контракт кампании и сохранений

## Переход между главами

`Game::campaign_state` извлекает сторону из `[scenario].campaign_side` и
возвращает:

- все её живые объекты на карте;
- уже находящихся в recall бойцов;
- переносимое золото `gold × carryover_percentage / 100`;
- все значения состояния, чьи ключи начинаются с `campaign:`.

Без `campaign_side` извлечение является ошибкой.

`Game::load_with_campaign` создаёт следующую главу из её WML. Если стартовый
`[unit]` имеет id сохранённого бойца, он получает сохранённые свойства и новую
сценарную позицию; отсутствующие сохранённые свойства дополняются текущим типом.
Остальные сохранённые бойцы попадают в recall. Кампанийные переменные добавляются
в состояние новой главы.

После `initialize` стартовое золото `campaign_side` становится максимумом из
перенесённого и настроенного сценарием. `next_scenario` возвращается только при
победе; финальная глава не обязана его задавать.

Стороны с одинаковым непустым `team_name` являются союзниками для атак, зон
контроля, видимости, деревень и дружественных способностей.

## Recall

`recall { unit, destination, leader? }` доступен человеку и требует:

- существующий id в recall;
- свободную клетку `castle`, связанную с `keep` подходящего лидера;
- лидера своей стороны на этом `keep`;
- не меньше `recall_cost` золота (по умолчанию 20).

Возвращённый боец сохраняет свойства, появляется без MP и атак до следующего
хода и удаляется из recall.

## Туман и исследование

При `fog=yes` статус содержит текущие `visible_cells` и `visible_units`.
Радиус берётся из стороны, затем сценария, затем равен 2. Обзор создают все
союзные бойцы. Скрытый противник не становится целью до обнаружения.

При `shroud=yes` `revealed_cells` накапливается отдельно для каждой стороны и
не уменьшается. Видимость пересчитывается после движения, найма, recall и
появления резервов.

## Сохранение текущей игры

`Game::save` сериализует JSON версии 1 со следующими данными:

- путь исходного сценария;
- все объекты и состояние;
- точное состояние RNG;
- ожидающий подтверждения диалог.

`Game::load_save` сначала заново загружает сценарий и правила, затем заменяет
объекты, состояние и RNG сохранёнными значениями. Версия, отличная от 1,
отклоняется. Восстановленное состояние должно успешно построить `status`, а
ожидающий диалог — существовать; иначе сохранение считается повреждённым.
Файловый загрузчик принимает только относительные пути внутри каталога
`scripts`. Поэтому сохранение воспроизводит продолжение той же партии, но
по-прежнему зависит от доступности исходных файлов сценария.

Кампанийный переход и сохранение партии — разные операции: первый намеренно
переносит только выбранное подмножество данных, второе восстанавливает весь
работающий мир.
