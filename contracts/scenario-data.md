# Контракт сценарных данных

## WML

Загрузчик принимает дерево из тегов, атрибутов и упорядоченных повторяющихся
дочерних тегов. Для первого сценария достаточно строк, целых чисел, списков
через запятую и многострочных значений `<< ... >>`.

Загрузчик только строит дерево. Значение тегов определяют Lua-правила.

## Ресурсы

`[resources]` связывает сценарий с файлами карты, объектов карты, типов юнитов,
диалогов и правил. Путь относителен `scripts/`. Ресурс загружается не более
одного раза; отсутствующий файл или повторяющийся id — ошибка загрузки.

## Данные первого среза

- `[scenario]`: `id`, `name`, `random_seed`, `on_start_dialog`;
- `[side]`: непрозрачные для движка атрибуты `id`, `controller`;
- `[unit]`: универсальный объект с `id`, `type`, `side`, `x`, `y`;
- `[objective]`: `result`, `when`, `unit`, `dialog`;
- `[map]`: `id`, `width`, `height`, прямоугольные строки `data`;
- `[map_object]`: определение непрозрачного значения ячейки;
- `[unit_type]`: свойства типа и повторяющиеся `[attack]`, `[defense]`,
  `[movement_costs]`;
- `[dialog]`: `id` и упорядоченные `[line]` с `speaker` и `text`.

Объект сценария получает собственные значения (`side`, позицию), а остальные
поля копируются из указанного типа правилами загрузки. В первом срезе текущее
`hitpoints` по умолчанию равно `max_hitpoints`.

## Валидация

До запуска проверяются уникальность id, существование ссылок, размер карты,
координаты объектов, отсутствие двух объектов в одной ячейке и наличие всех
обязательных полей. Движок проверяет форму данных; игровые ограничения
проверяют Lua-правила.
