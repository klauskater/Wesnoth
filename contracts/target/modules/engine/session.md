# Контракт engine/session

Статус: **реализован**. Редакция проекта: 1. Session предоставляет только
контрактные lifecycle/dispatch/interact/present/snapshot/save/restore границы,
единолично выполняет commit, хранит revision/dedup и контексты наблюдателей.
Прежний именованный query удалён; Game-адаптер преобразует чтение в
Interaction и получает результат из ViewBlock без обхода Session. Open выполняет
initialize атомарно, а успешный restore назначает новую session identity.
Поставщик: `src/engine/session.rs`.
[Карточка модуля](../../../../design/architecture/modules/engine/session.md).
Обязательны [общие соглашения](../../common.md) и [поток сообщений](../../stream.md).

## Назначение

Оркестрация жизненного цикла сессии и последовательной обработки входа.

## Потребители и зависимости

Потребители: [client/connection](../client/connection.md).

Использует контракты: [engine/runtime](../engine/runtime.md), [engine/store](../engine/store.md), [engine/protocol](../engine/protocol.md), [engine/resources](../engine/resources.md), [engine/persistence](../engine/persistence.md).
Ссылка Lua → engine означает возможность host API через ctx, а не импорт Rust из Lua.
Обратная ссылка потребителя не разрешает обратный вызов или циклический импорт.

## Операции: вход → выход

```text
open(package, request) -> Session
dispatch(viewer, Command) -> CommandResult
interact(viewer, Interaction) -> ViewDelivery
snapshot(viewer) -> ViewSnapshot
save() -> Save
restore(Save) -> Session
```

Это обязательные логические формы, не готовые Rust-сигнатуры. Общие типы определены
в common.md; специфичные типы текущей игры используют её сохранённую семантику,
описанную в [таблице соответствия](../../README.md#прежние-документы).
Конкретный wire layout и имена полей этих игровых записей уточняются в данном
контракте до переключения вызывающих, а не скрыто внутри реализации.

## Гарантии и результат

Сериализует команды. Viewer определяется подключением. Управляет commit и построением view, хранит отдельные контексты наблюдателей. Использует stream.md.

## Ошибки и побочные эффекты

Повтор command_id с тем же содержимым возвращает прежний результат; тот же id с другим содержимым -> conflict. Ошибка present после commit не отменяет команду: отправляется committed result и требуется snapshot.

## Владение данными

Очередь команд, идентификатор сессии, контекст каждого наблюдателя и кеш его последнего представления.

## Что не входит в контракт

Не знает ходов, юнитов, AI-сторон и условий победы. Не вычисляет содержимое панелей.

## Приёмка реализации

Старая команда отклоняется; ошибка present после commit допускает повторное построение без повторного выполнения команды.

Перенос из: src/game.rs и часть orchestration клиента.
При внедрении добавить ссылку `Контракт: contracts/target/modules/engine/session.md`
в заголовок файла поставщика. Статус меняется на «реализован» только вместе
с реализацией, переведёнными потребителями и результатом проверки.
