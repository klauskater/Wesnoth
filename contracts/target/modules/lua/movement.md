## Назначение

Правила перемещения и достижимости.

## Потребители и зависимости

Потребители: [lua/flow](../lua/flow.md), [lua/visibility](../lua/visibility.md), [lua/ai](../lua/ai.md), [lua/interaction](../lua/interaction.md), [lua/map](../lua/map.md).

Использует контракты: [lua/sides](../lua/sides.md), [lua/terrain](../lua/terrain.md), [lua/units](../lua/units.md), [engine/pathfinding](../engine/pathfinding.md), [engine/store](../engine/store.md).
Ссылка Lua → engine означает возможность host API через ctx, а не импорт Rust из Lua.
Обратная ссылка потребителя не разрешает обратный вызов или циклический импорт.

## Операции: вход → выход

```text
reachable(read,unit_id) -> Reachability
validate_move(read,request) -> MovePlan
move(tx,request) -> DomainEvents
```

Это обязательные логические формы, не готовые Rust-сигнатуры. Общие типы определены
в common.md; специфичные типы текущей игры используют её сохранённую семантику,
описанную в [таблице соответствия](../../README.md#прежние-документы).
Конкретный wire layout и имена полей этих игровых записей уточняются в данном
контракте до переключения вызывающих, а не скрыто внутри реализации.

## Гарантии и результат

Request = {unit_id,destination}; MovePlan содержит путь и расходы. Move повторно проверяет текущие данные, возвращает факты входа на клетки; capture/триггеры организует flow.

## Ошибки и побочные эффекты

Чужой юнит, занятость, недостаток MP или запрещённый путь -> Error без частичного хода. Предпросмотр и исполнение используют одну подготовку весов.

## Владение данными

Правила MP, занятости и ZOC; записи позиции и MP через tx.

## Что не входит в контракт

Не вызывает боевой resolve и не запускает сценарные события сам; возвращает факты перемещения в flow.

## Приёмка реализации

Предпросмотр и выполнение используют одинаковые ограничения; вход в ZOC завершает движение по правилам.

Перенос из: basic_combat.reachable/move; игровая часть src/pathfinding.rs.
При внедрении добавить ссылку `Контракт: contracts/target/modules/lua/movement.md`
в заголовок файла поставщика. Статус меняется на «реализован» только вместе
с реализацией, переведёнными потребителями и результатом проверки.
