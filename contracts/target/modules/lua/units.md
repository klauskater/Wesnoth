# Контракт lua/units

Статус: **целевой, не реализован**. Редакция проекта: 1.
Поставщик: `scripts/game/rules/units.lua`.
[Карточка модуля](../../../../design/architecture/modules/lua/units.md).
Обязательны [общие соглашения](../../common.md) и [поток сообщений](../../stream.md).

## Назначение

Создание и изменение юнитов по каталогам, traits и развитию.

## Потребители и зависимости

Потребители: [lua/bootstrap](../lua/bootstrap.md), [lua/flow](../lua/flow.md), [lua/movement](../lua/movement.md), [lua/combat](../lua/combat.md), [lua/time](../lua/time.md), [lua/turns](../lua/turns.md), [lua/economy](../lua/economy.md), [lua/visibility](../lua/visibility.md), [lua/scenario](../lua/scenario.md), [lua/campaign](../lua/campaign.md), [lua/map](../lua/map.md), [lua/hud](../lua/hud.md).

Использует контракты: [engine/store](../engine/store.md).
Ссылка Lua → engine означает возможность host API через ctx, а не импорт Rust из Lua.
Обратная ссылка потребителя не разрешает обратный вызов или циклический импорт.

## Операции: вход → выход

```text
create(tx,type_id,overrides) -> UnitId
apply_traits(tx,id,traits) -> DomainEvents
grant_experience(tx,id,amount) -> DomainEvents
advancement_options(read,id) -> Option[]
advance(tx,id,choice) -> DomainEvents
```

Это обязательные логические формы, не готовые Rust-сигнатуры. Общие типы определены
в common.md; специфичные типы текущей игры используют её сохранённую семантику,
описанную в [таблице соответствия](../../README.md#прежние-документы).
Конкретный wire layout и имена полей этих игровых записей уточняются в данном
контракте до переключения вызывающих, а не скрыто внутри реализации.

## Гарантии и результат

Схема юнита принадлежит игре. Изменения применяются к store; чтение способностей/traits не мутирует каталоги. Размер XP задаёт вызывающее правило, не UI.

## Ошибки и побочные эффекты

Неизвестный тип/юнит/выбор или недопустимые свойства -> Error. Развитие сохраняет переносимые свойства и лишний XP по правилам текущей игры.

## Владение данными

Схема свойств юнита и преобразований типа; сами записи находятся в store.

## Что не входит в контракт

Не решает, сколько XP даётся за конкретное событие боя: это передаёт flow по правилам игры; не управляет UI выбора.

## Приёмка реализации

Развитие сохраняет положенные свойства, переносит XP и создаёт ожидаемый выбор.

Перенос из: basic_combat apply_trait_effect/apply_advancement/advance_unit; загрузка unit types из Rust.
При внедрении добавить ссылку `Контракт: contracts/target/modules/lua/units.md`
в заголовок файла поставщика. Статус меняется на «реализован» только вместе
с реализацией, переведёнными потребителями и результатом проверки.
