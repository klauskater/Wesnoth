# Контракт lua/forecast

Статус: **целевой, не реализован**. Редакция проекта: 1.
Поставщик: `scripts/game/rules/forecast.lua`.
[Карточка модуля](../../../../design/architecture/modules/lua/forecast.md).
Обязательны [общие соглашения](../../common.md) и [поток сообщений](../../stream.md).

## Назначение

Прогноз вероятностей исходов боя без изменения мира.

## Потребители и зависимости

Потребители: [lua/ai](../lua/ai.md), [lua/hud](../lua/hud.md).

Использует контракты: [lua/combat](../lua/combat.md).
Ссылка Lua → engine означает возможность host API через ctx, а не импорт Rust из Lua.
Обратная ссылка потребителя не разрешает обратный вызов или циклический импорт.

## Операции: вход → выход

```text
forecast(PreparedBattle) -> {outcomes,summary}
```

Это обязательные логические формы, не готовые Rust-сигнатуры. Общие типы определены
в common.md; специфичные типы текущей игры используют её сохранённую семантику,
описанную в [таблице соответствия](../../README.md#прежние-документы).
Конкретный wire layout и имена полей этих игровых записей уточняются в данном
контракте до переключения вызывающих, а не скрыто внутри реализации.

## Гарантии и результат

Каждый outcome содержит конечное боевое состояние и конечную вероятность >=0; сумма равна 1 с допуском 1e-9. Использует чистый combat.step; полный ключ входов определяет кеш.

## Ошибки и побочные эффекты

Некорректные параметры/превышенный лимит расчёта -> Error, не выдуманный прогноз. Не меняет RNG/мир; ошибка прогноза не выполняет бой.

## Владение данными

Временные ветви вероятностей, без авторитетного состояния.

## Что не входит в контракт

Не потребляет игровой RNG. Rust combat kernel с slow/petrify переносится сюда; новый универсальный native kernel заранее не проектируется.

## Приёмка реализации

Прогноз и исполнение совпадают на детерминированных случаях и случаях со статусами; измерены время и размер кеша.

Перенос из: src/combat.rs forecast; basic_combat.preview_attack.
При внедрении добавить ссылку `Контракт: contracts/target/modules/lua/forecast.md`
в заголовок файла поставщика. Статус меняется на «реализован» только вместе
с реализацией, переведёнными потребителями и результатом проверки.
