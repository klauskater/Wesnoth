# Контракт lua/presenter

Статус: **частично реализован**. Редакция проекта: 1. Read-only presenter строит
стабильные status/objects/HUD/time блоки, статические terrain scene/map/asset registry,
диалоги, эффекты, выбранную клетку с готовыми названием местности и строками
юнита, навигацию к следующему доступному юниту, маршрут с уже вычисленной
защитой и attack-блок с допустимым
оружием и read-only прогнозами боя, summary, unit и recruit UiNode-блоки.
Динамические scene items, viewer-фильтрация и остальные панели ещё переносятся.
Поставщик: `scripts/game/presentation/presenter.lua`.
[Карточка модуля](../../../../design/architecture/modules/lua/presenter.md).
Обязательны [общие соглашения](../../common.md) и [поток сообщений](../../stream.md).

## Назначение

Сборка представления конкретного наблюдателя после изменения мира или взаимодействия.

## Потребители и зависимости

Потребители: [lua/entry](../lua/entry.md).

Использует контракты: [lua/map](../lua/map.md), [lua/hud](../lua/hud.md), [lua/effects](../lua/effects.md), [lua/visibility](../lua/visibility.md).
Ссылка Lua → engine означает возможность host API через ctx, а не импорт Rust из Lua.
Обратная ссылка потребителя не разрешает обратный вызов или циклический импорт.

## Операции: вход → выход

```text
present(read,viewer,view_context,changes,events) -> Presentation
```

Это обязательные логические формы, не готовые Rust-сигнатуры. Общие типы определены
в common.md; специфичные типы текущей игры используют её сохранённую семантику,
описанную в [таблице соответствия](../../README.md#прежние-документы).
Конкретный wire layout и имена полей этих игровых записей уточняются в данном
контракте до переключения вызывающих, а не скрыто внутри реализации.

## Гарантии и результат

Presentation = {replace_blocks,remove_ids,effects}; first/rebuild строит полный набор блоков. Session назначает view_revision. Viewer-фильтрация обязательна для UI, scene, hit ids и эффектов.

## Ошибки и побочные эффекты

Ошибка построения -> Error без записи/игрового RNG; повторное построение даёт те же effect ids. Неизвестная зависимость ChangeSet приводит к перестройке блока.

## Владение данными

Кеши блоков по world_revision, viewer и interaction_revision; всё можно пересоздать.

## Что не входит в контракт

Не меняет мир и RNG. При неизвестной зависимости перестраивает блок, а не оставляет устаревшее значение.

## Приёмка реализации

Смена выбора обновляет UI без world commit; ошибка построения допускает повторный present.

Перенос из: basic_combat.snapshot/status/actions; GameSnapshot; screens/game.rs.
При внедрении добавить ссылку `Контракт: contracts/target/modules/lua/presenter.md`
в заголовок файла поставщика. Статус меняется на «реализован» только вместе
с реализацией, переведёнными потребителями и результатом проверки.
