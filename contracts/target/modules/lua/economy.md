# Контракт lua/economy

Статус: **целевой, не реализован**. Редакция проекта: 1.
Поставщик: `scripts/game/rules/economy.lua`.
[Карточка модуля](../../../../design/architecture/modules/lua/economy.md).
Обязательны [общие соглашения](../../common.md) и [поток сообщений](../../stream.md).

## Назначение

Золото, доход, содержание, владение деревнями и найм/возврат.

## Потребители и зависимости

Потребители: [lua/flow](../lua/flow.md), [lua/turns](../lua/turns.md), [lua/ai](../lua/ai.md), [lua/interaction](../lua/interaction.md), [lua/hud](../lua/hud.md).

Использует контракты: [lua/units](../lua/units.md), [lua/sides](../lua/sides.md), [lua/terrain](../lua/terrain.md), [engine/store](../engine/store.md).
Ссылка Lua → engine означает возможность host API через ctx, а не импорт Rust из Lua.
Обратная ссылка потребителя не разрешает обратный вызов или циклический импорт.

## Операции: вход → выход

```text
balance(read,side) -> Balance
accrue(tx,side) -> DomainEvents
capture(tx,unit_id,position) -> DomainEvents
recruit_options(read,side) -> Option[]
recruit(tx,request) -> DomainEvents
recall(tx,request) -> DomainEvents
```

Это обязательные логические формы, не готовые Rust-сигнатуры. Общие типы определены
в common.md; специфичные типы текущей игры используют её сохранённую семантику,
описанную в [таблице соответствия](../../README.md#прежние-документы).
Конкретный wire layout и имена полей этих игровых записей уточняются в данном
контракте до переключения вызывающих, а не скрыто внутри реализации.

## Гарантии и результат

Request содержит выбранный тип/резерв и гекс, не доверенную цену. Золото, резерв, владелец деревни записываются в той же Tx.

## Ошибки и побочные эффекты

Неверный лидер/гекс/тип, недостаток золота -> Error без списания/создания юнита. Стоимость вычисляется тем же правилом, что варианты UI.

## Владение данными

Золото, владельцы деревень и резерв в store; стоимость и ограничения найма.

## Что не входит в контракт

Не отображает магазин и не переносит кампанию. Нельзя доверять цене, переданной клиентом.

## Приёмка реализации

Невалидный найм не списывает золото; recruit_options согласован с recruit.

Перенос из: economy/village_at/recruitment_hexes/recruit/recall в basic_combat.lua.
При внедрении добавить ссылку `Контракт: contracts/target/modules/lua/economy.md`
в заголовок файла поставщика. Статус меняется на «реализован» только вместе
с реализацией, переведёнными потребителями и результатом проверки.
