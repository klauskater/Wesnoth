# Контракт client/effects

Статус: **целевой, не реализован**. Редакция проекта: 1.
Поставщик: `src/bin/client/effects.rs`.
[Карточка модуля](../../../../design/architecture/modules/client/effects.md).
Обязательны [общие соглашения](../../common.md) и [поток сообщений](../../stream.md).

## Назначение

Воспроизведение одноразовых визуальных и звуковых эффектов.

## Потребители и зависимости

Потребители: [client/app](../client/app.md).

Использует контракты: [client/view](../client/view.md), [client/scene](../client/scene.md), [engine/protocol](../engine/protocol.md).
Ссылка Lua → engine означает возможность host API через ctx, а не импорт Rust из Lua.
Обратная ссылка потребителя не разрешает обратный вызов или циклический импорт.

## Операции: вход → выход

```text
play(Effect[]) -> Unit
tick(elapsed) -> VisualOverrides
skip() -> Unit
reset() -> Unit
```

Это обязательные логические формы, не готовые Rust-сигнатуры. Общие типы определены
в common.md; специфичные типы текущей игры используют её сохранённую семантику,
описанную в [таблице соответствия](../../README.md#прежние-документы).
Конкретный wire layout и имена полей этих игровых записей уточняются в данном
контракте до переключения вызывающих, а не скрыто внутри реализации.

## Гарантии и результат

Стабильные effect ids не проигрываются повторно в сессии; последовательность временно визуализирует уже committed мир. Reset при смене сессии очищает историю.

## Ошибки и побочные эффекты

Неизвестный визуальный ресурс даёт техническую ошибку без отката мира; skip завершает визуализацию и не исполняет command.

## Владение данными

Локальная временная шкала и проигрываемые эффекты.

## Что не входит в контракт

Не применяет урон и не задерживает commit до конца анимации. Не интерпретирует unit_killed: Lua переводит это в визуальный эффект.

## Приёмка реализации

Повторная доставка effect_id не воспроизводит его дважды; пропуск анимации не меняет мир.

Перенос из: src/bin/client/battle.rs; movement.rs.
При внедрении добавить ссылку `Контракт: contracts/target/modules/client/effects.md`
в заголовок файла поставщика. Статус меняется на «реализован» только вместе
с реализацией, переведёнными потребителями и результатом проверки.
