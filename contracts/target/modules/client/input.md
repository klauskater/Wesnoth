# Контракт client/input

Статус: **целевой, не реализован**. Редакция проекта: 1.
Поставщик: `src/bin/client/input.rs`.
[Карточка модуля](../../../../design/architecture/modules/client/input.md).
Обязательны [общие соглашения](../../common.md) и [поток сообщений](../../stream.md).

## Назначение

Преобразование физического ввода в универсальные взаимодействия.

## Потребители и зависимости

Потребители: [client/app](../client/app.md).

Использует контракты: [client/view](../client/view.md), [client/viewport](../client/viewport.md), [engine/protocol](../engine/protocol.md).
Ссылка Lua → engine означает возможность host API через ctx, а не импорт Rust из Lua.
Обратная ссылка потребителя не разрешает обратный вызов или циклический импорт.

## Операции: вход → выход

```text
translate(raw_input, hit_regions, camera) -> LocalActions + Interaction[] + Command[]
```

Это обязательные логические формы, не готовые Rust-сигнатуры. Общие типы определены
в common.md; специфичные типы текущей игры используют её сохранённую семантику,
описанную в [таблице соответствия](../../README.md#прежние-документы).
Конкретный wire layout и имена полей этих игровых записей уточняются в данном
контракте до переключения вызывающих, а не скрыто внутри реализации.

## Гарантии и результат

Кнопка передаёт выданный action; карта отправляет координату/id. enabled=false не создаёт command. Camera/scroll/focus локальны; hover только при смене цели.

## Ошибки и побочные эффекты

Hit из устаревшего view несёт его revision и проверяется session. Input не решает, означает клик атаку или движение.

## Владение данными

Жесты, фокус, подавление повторного hover внутри одного гекса.

## Что не входит в контракт

Не решает, означает ли клик выбор, движение или атаку; это решает presentation/interaction.lua.

## Приёмка реализации

Одна смена hovered-гекса создаёт одно Interaction; enabled=false не отправляет действие.

Перенос из: screens/game.rs input; widgets.rs.
При внедрении добавить ссылку `Контракт: contracts/target/modules/client/input.md`
в заголовок файла поставщика. Статус меняется на «реализован» только вместе
с реализацией, переведёнными потребителями и результатом проверки.
