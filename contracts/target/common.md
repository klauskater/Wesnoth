# Общие соглашения целевых контрактов

Статус: целевые, не реализованы. Редакция проекта: 1.

Контракт — обязательства поставщика перед потребителем: допустимые входы,
выходы, порядок, гарантии, ошибки и побочные эффекты. Интерфейс — только часть
контракта, выраженная функциями и типами. Общий Rust trait для каждого модуля
не требуется: обычный модуль с функциями и типами может выполнять контракт.

## Статус и изменение

Пока статус «целевой», документ задаёт направление миграции, а не факт о коде.
До перевода первого вызывающего конкретизируются все используемые им типы
и варианты ошибок; неопределённую структуру нельзя считать реализованным API.
Переход к «реализован» включает модульный комментарий со ссылкой на контракт,
перевод потребителей и проверку гарантий. Частично перенесённый контракт
перечисляет реализованные операции отдельно; целый документ не закрывается.

Несовместимое изменение внешних сообщений требует новой protocol_version.
Внутренние контракты меняются атомарно с вызывающими; отдельное версионирование
каждой функции не нужно. Редакция проекта — версия документа, не wire version.

## Типы

- Id: непустая строка; Position: {x: Int, y: Int}; размеры карты положительны.
- Revision: неотрицательное монотонное целое в пределах сессии. При исчерпании
  диапазона ошибка/новая сессия, не wraparound.
- Value определён в [engine/value](modules/engine/value.md). Optional<Value>
  отличает отсутствие записи от существующей записи Null.
- ReadView: неизменяемый доступ к одной согласованной ревизии, без игрового RNG.
- Tx: read view + незавершённые записи + транзакционный RNG. Модуль правил не
  может самостоятельно commit. Контекст действителен только во время вызова.
- DomainEvent: {kind: String, payload: Value}; типы событий принадлежат Lua-игре.
- ChangeSet: изменённые адреса store и итоговая world_revision; это не журнал
  боевых событий и не готовый патч интерфейса.
- Command/Interaction/View/Effect: [stream](stream.md).
- Presentation: заменяемые блоки, удаляемые ids и видимые эффекты, без ревизий;
  Session присваивает ревизии и формирует Snapshot/Update.
- InteractionResult: {view_context: Value, command?: {action, payload}}.
  Session связывает полученную command с interaction_id для дедупликации,
  назначает actor и текущую проверенную world_revision.
- Unit/Side/PreparedBattle/Carryover и подобные типы — структуры пакета игры.
  Их поля не становятся типами или branch conditions Rust-хоста/клиента.

Пока игровой wire layout не уточнён, источники прежней семантики указаны
в [реестре](README.md#прежние-документы). Типы новых границ конкретизируются до
их реализации; это явно незавершённая детализация проекта, не обещание готового ABI.

## Ошибки

Логическая Error = {code, message, details?}. Базовые code: invalid_input,
not_found, conflict, forbidden, incompatible_version, resource_error,
script_error, budget_exceeded. Игра может уточнять причину в details.
Сообщение для наблюдателя не раскрывает скрытые игровые данные или host paths.

Read-only ошибка не меняет мир. Ошибка dispatch до commit откатывает записи
и RNG всей команды. Ошибка визуализации после commit не откатывает мир;
клиент восстанавливает представление отдельно. Пустой список — допустимый
результат, если нет элементов; ошибка не маскируется пустым списком.

## Побочные эффекты и стоимость

Правила и инициализация изменяют только Tx. Запросы, AI, forecast и presentation
не изменяют авторитетное состояние. Локальные кеши разрешены, если сброс кеша
не меняет результат. Запись UI, звук и GPU находятся в клиенте.

Межмодульный вызов Lua не является переходом в Rust. Хост передаёт ограниченный
ctx и пакет нужных данных, а не весь мир на каждый вызов.
На неизменный кадр, движение камеры и layout нет входов в Lua.
Всем контрактам запрещено вводить per-cell native → Lua callback в поиске пути.

## Единственный источник каждого решения

Карточка архитектуры: ответственность и место модуля.
Контракт модуля: API, владение на границе, гарантии и ошибки.
Stream: общие сообщения и последовательность.
Действующая документация старого API: только до переключения его потребителей.
Дублировать сигнатуры в архитектурных карточках не нужно.
